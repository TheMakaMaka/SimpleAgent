# 标定方案（Spec）

**一句话**：后端把「自己长什么样」声明出来，前端照单渲染，前端不写死任何后端事实。

在这之前，"低定制"是假的——阶段名、事件词表、工具名、状态色、轮询间隔
**全写死在前端代码里**。后端一改（加阶段、改事件名、加工具），前端就得跟着改。

现在：

```
bridge/spec.py  ──GET /api/spec──▶  frontend
   声明事实与标定                     照单渲染
```

---

## 1. 事实 / 标定 / 渲染，三层分清楚

| 层 | 内容 | 谁维护 | 能不能改 |
|---|---|---|---|
| **事实** | 有哪些阶段、哪些事件、哪些工具 | **从代码扫出来**，不手写 | ❌ 改不动（改了就和代码说谎） |
| **标定** | 中文名、色调、归到哪个面板、可调参数 | `bridge/spec.py` 的 `CALIBRATION` | ✅ 可改，也可被 `spec.override.json` 覆盖 |
| **渲染** | 怎么画 | `frontend/src/**` | ✅ 可改，但它不含任何后端事实 |

事实怎么扫的：

| 事实 | 来源 |
|---|---|
| 阶段清单 | 上游 `core.cycle.PHASE_ORDER` |
| 门禁步骤（MANIFEST） | 标定里的 `gate_after`（声明它插在哪个阶段之后） |
| 事件词表 | AST 扫三处：上游 `_emit` / `bridge/hooks.py` / `bridge/runner.py` |
| 工具清单 | 上游 `tools.registry.TOOLS_MAP`（名字、描述、profile） |
| 端点 | `bridge/spec.py` 的 `ENDPOINTS`（这些是 bridge 自己的，所以这里就是权威） |

**为什么事实必须扫而不是手写**：手写的一定会漂移。§17 那个
「前端认的事件和后端发的不一致」的问题，根因就是两边各手写了一份。

---

## 2. 你能改什么：三种方式

### 方式 A：`spec.override.json`（推荐，零代码）

放**仓库根**，覆盖任意标定项。见 `spec.override.example.json`。

```json
{
  "stage_labels": { "plan": "规划" },
  "ui": {
    "poll": { "health_ms": 15000 },
    "examples": [
      { "label": "我的任务", "goal": "...", "verify": "..." }
    ]
  }
}
```

**不用改代码，不用重新构建前端**（改 `ui` 段连重启都不用，刷新页面即可）。

### 方式 B：改 `bridge/spec.py` 的 `CALIBRATION`

想改默认值（对所有环境生效）就改这里。文件里每一段都有注释说明字段含义。

### 方式 C：改前端渲染

`frontend/src/components/**`。改的是**长相**，不是事实与标定。

## 3. 预留接口：后端加东西，前端自动跟上

| 后端做了什么 | 前端会怎样 | 要改前端吗 |
|---|---|---|
| 上游给 `PHASE_ORDER` 加一个阶段 | 流水线自动多一个节点，label = 阶段名大写 | **不用** |
| 加一个门禁步骤 | 在 `gate_after` 里声明插入点，自动多一个节点 | **不用** |
| 加一个事件 | 按标定的 label/tone 渲染；没标定就自动生成可读名字 | **不用** |
| 加一个工具 | 工具面板显示它；中文名没标就显示原名 | **不用** |
| 改端点路径 | 前端从 `spec.endpoints` 拿，跟着走 | **不用** |
| 改轮询间隔 / 示例任务 / 面板开关 | 从 `spec.ui` 拿 | **不用** |

**认不出的东西一律降级，不报错、不空白**：

- 未知阶段 → 运行时补一个节点（通用图标 + `（标定里未声明，按运行时补上）`）
- 未知事件 → 标定没有就用自动生成的 label + 从 payload 自动挑一个可读字段
- 未知图标名 → 通用图标（一个加号，一眼看出"这个前端没见过"）
- 未知状态 → 显示原始字符串
- 标定端点拿不到 → 用前端内置的 `DEFAULT_SPEC`，界面照常可用

> 崩了比显示不出来严重得多。所以这里全部选择"降级可见"。

## 4. 三把锁（防止"低定制"退化成口号）

| 测试 | 守什么 |
|---|---|
| `tests/unit/test_spec.py` | 事实 == 代码现状；没有漏标/死标；**端点声明与真实路由双向一致**；**前端兜底 `DEFAULT_SPEC` 不许漂**；override 能改标定但**改不了事实** |
| `tests/unit/test_event_contract.py` | 前端认得的事件 == 后端会发的（跨语言词表一致性） |
| `tests/unit/test_isolation.py` | `backend/` 保持纯上游；运行根在任意 CWD 下生效 |

其中 **"前端兜底不许漂"** 最容易被忽略：`DEFAULT_SPEC` 是后端拿不到时的备用值，
它和真 spec 之间**没有类型系统帮忙**，只能靠测试盯。

## 5. 看当前标定

```bash
curl http://127.0.0.1:8000/api/spec
```

重点看 `diagnostics` 段：

```json
{
  "event_count": 33,
  "uncalibrated_events": [],        // 非空 → 有事件没标定，会显示自动生成的名字
  "dead_calibrations": [],          // 非空 → 标了但代码不发，多半上游删了事件
  "override_file": "…/spec.override.json",
  "errors": []                      // 非空 → override 文件写错了
}
```

## 6. 尚未做

- **没有前端设置面板**：现在改标定要编辑 JSON。加个界面直接改也行，
  但会引入"设置存哪儿、谁有权限"的新问题，先不做。
- **图标库是内置的**：标定只能选名字，不能传 SVG。要传图还得再开一层。
- **`failure_phase` 仍然是上游的 `failed`**：标定里留了键，但改成别的值没有意义，
  因为它是上游 `CyclePhase` 的一部分。
